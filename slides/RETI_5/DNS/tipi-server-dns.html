Dominie zone

Il DNS è un unico albero di nomi, ma nessuno lo gestisce tutto. L’albero è diviso in zone, e ogni zona ha i suoi server autoritativi.

Dominio

Un nodo dell’albero e tutto ciò che sta sotto di lui.

Zona

La parte di albero gestita da un’unica autorità. Finisce dove inizia una delega.

Delega

Record NS nella zona padre che affidano un sottodominio ad altri server.

Lo stesso albero, diviso in zone

Ogni area tratteggiata è una zona. La linea viola è un taglio di delega.

Il file di zona di example.it.

Sta sul server primario: è qui che si scrivono i record.

$TTL 3600
@      IN SOA ns1.example.it. admin.example.it. (
             2026102201 ; serial
             7200       ; refresh
             900        ; retry
             1209600    ; expire
             3600 )     ; TTL negativo
       IN NS  ns1.example.it.
       IN NS  ns2.example.it.
       IN MX  10 mail.example.it.
ns1    IN A   192.0.2.53
ns2    IN A   198.51.100.53
www    IN A   192.0.2.10
mail   IN A   192.0.2.25
; delega della sottozona
lab    IN NS  ns.lab.example.it.
ns.lab IN A   192.0.2.80  ; glue
Dominio ≠ zona

lab.example.it fa parte del dominio example.it, ma non della sua zona: è delegato con un record NS ed è servito da altri server autoritativi.

Chi cerca,chi risponde

I tipi di server DNS divisi per ruolo: chi va a cercare le risposte e chi possiede le zone in cui sono scritte.

RD

Recursion desired: chi chiede vuole che il server risolva per lui.

RA

Recursion available: il server accetta di risolvere per il client.

AA

Authoritative answer: risponde chi ospita la zona.

Risolutori

chi cerca le risposte

Stub resolver

glibc, client DNS di Windows

Vive nel sistema operativo e non risolve nulla da solo: invia una query ricorsiva al server configurato e attende la risposta finale.

invia RD=1cache: minima

Forwarder con cache

systemd-resolved, dnsmasq

Accetta query ricorsive dai client. Risponde dalla cache oppure inoltra a un resolver ricorsivo upstream. Non contatta mai i root server.

RA=1cache: sì

Resolver ricorsivo

Unbound, BIND, 1.1.1.1

Parte dai root hints e segue i referral, interrogando in modo iterativo root, TLD e autoritativi. Conserva ogni risposta in cache per il suo TTL.

RA=1cache: sìAA=0

Server autoritativi

chi possiede le risposte

Root server

a … m.root-servers.net

Ospitano la zona radice e rispondono con un referral verso il TLD. Sono 13 identità servite da centinaia di istanze anycast.

referralzona .

Server TLD

a.dns.it, gtld-servers.net

Ospitano la zona del dominio di primo livello con le deleghe a ogni dominio registrato e rimandano ai suoi autoritativi.

referralDS

Primario

BIND, NSD, PowerDNS, Knot

È la fonte di verità della zona: qui l’amministratore aggiunge e modifica i record. A ogni modifica incrementa il serial del SOA, il numero di versione della zona.

AA=1modificabile

Secondario

stessi software, su un altro host

Copia in sola lettura della zona. Avvisato dal primario con un NOTIFY, confronta il serial e, se è cambiato, scarica la zona via AXFR o IXFR (TCP/53).
